# Bluetooth MIDI host on Felucca 1.6: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A gated `FELUCCA_BLE=1` build of Felucca 1.6 that is a Bluetooth LE MIDI central (scan, connect, MIDI in
and out, BLE clock, a Bluetooth menu page, the SMC-Mixer DAW mode), while the plain build stays byte-identical to
tag `v1.6`.

**Architecture:** Hortator's BLE unit (`firmware/src/ble/`, its own compilation unit behind `ble_core.h`) is
copied as it is and linked with the pinned JieLi BT libraries through LTO. The core's side (`core_ble_api.c`,
`bt_set.c`, `bt_midi.c`, `bt_page.c`, `smc.c`) is written against 1.6 and included by `felucca.c` only under
`#if FELUCCA_BLE`. `tools/build.py` gains the Bluetooth link and the gates.

**Tech stack:** C (JieLi clang 4.0.1 for pi32v2, in Docker), Python 3 build tools, host tests compiled with the
machine's `cc` (`tests/run_tests.sh`).

**Spec:** `docs/superpowers/specs/2026-10-13-ble-midi-design.md`

**Source of the copied files:** `~/Desktop/dev/fm1-drummachine/felucca-midi` (Hortator, branch `midi`, f3d7e5a),
called `$H` below. This tree is `$T`. A step that says "copy" means the file is taken byte for byte; a step that
says "port" means the Hortator file is the model and the code is written against 1.6's functions, read at that
step. New code is not repeated in this plan: the interfaces, the tests' assertions and the acceptance commands are.

**Build commands** (the venv has Pillow and fontTools):
```sh
export PYTHON=~/.claude/jobs/21001013/tmp/venv/bin/python3     # any python3 with Pillow + fonttools
./build.sh                                   # plain
FELUCCA_BLE=1 ./build.sh                     # Bluetooth, every gate
FELUCCA_BLE=1 BLE_MEASURE=1 ./build.sh       # measuring only (regions widened, never packaged)
sh tests/run_tests.sh                        # after a plain ./build.sh
```
The pristine v1.6 build for comparisons is `~/.claude/jobs/21001013/tmp/upstream/felucca-1.6/build/`.

## Global constraints

- The plain build's `build/felucca.bin` equals tag `v1.6`'s, byte for byte. Every edit to an existing source file is
  inside `#if FELUCCA_BLE`.
- The update loader's `ota.bin` equals v1.6's; its sha256 is pinned in `tools/ble_base.txt`.
- The Bluetooth image leaves at least 32,768 B of the 581,564 B slot free; `.data + .bss` keeps 4,096 B spare of
  73,728; `.pool` keeps 8,192 B spare of 368,640.
- No update-path source changes: `firmware/src/usb.c`, `ota.c`, `ota_hw.c`, `storage.c`, `storage_hw.c`, `libc.c`,
  `main.c`, `firmware/crt0.S`, `firmware/app.ld`, `firmware/hal/*` (existing), `firmware/loader/*`.
- Nothing Bluetooth starts at boot. `ble_user_start` is referenced only from `ble_console` and `bt_page_on`.
- No flash write from `firmware/src/ble/`. Integer only in project code.
- Register access only in `firmware/hal/`.
- New files carry `SPDX-License-Identifier: GPL-3.0-only` and `BLE MIDI: 2026 DEADACTIVE`; copied files keep their
  headers.
- Commit after every task; messages in the repository's style (what changed, plainly), ending with the
  `Co-Authored-By` line.

## Review focus

1. **The link drops while notes from BLE are held** (the controller is switched off): the notes are released, as
   1.6 does for a pulled USB cable. Test in Task 4.
2. **A burst of BLE input when the MIDI ring is nearly full** (a fader sweep while USB also sends): BLE packets are
   dropped and counted, the ring's overflow flag (which makes the audio side discard and release everything) is
   never set by BLE. Test in Task 4.
3. **Settings bytes that are not ours** (all zero from an older record, or garbage with a wrong check byte): no
   device, MODE AUTO, nothing connects. Test in Task 4.
4. **A project with CLK BLE opened by the plain build:** it must not index past the clock names. Checked against
   1.6's load clamp in Task 4; if the plain build would misread value 3, the Bluetooth build stores CLK BLE in the
   project as INT and keeps BLE as a runtime choice instead.
5. **Device names that are long or not ASCII** (23 bytes, bytes above 0x7F) on the page: drawn clipped inside their
   column, no overlap. Test in Task 5.

### Task 4: Settings, MIDI mode in and out, CLK BLE

**Files:** Create `firmware/src/bt_set.c`, `firmware/src/bt_midi.c`, `tests/bt_midi_test.c`. Modify `felucca.c`

**Interfaces — produces:**
```c
/* bt_set.c: favorites.factory[13][24..31] = addr[6], flags (bits 0-1 MODE, bit 2 type), check */
enum { BT_MODE_AUTO, BT_MODE_SMC, BT_MODE_MIDI };
typedef struct { uint8_t addr[6], type, mode, has; } bt_set_t;      /* has = a device is remembered */
static void bt_set_get(bt_set_t *s);        /* bad check byte or all zero: has 0, mode AUTO */
static void bt_set_put(const bt_set_t *s);  /* writes the bytes and calls settings_save() */
/* bt_midi.c */
static struct { uint32_t drops, out_drops; uint8_t smc; } bt_in;
static void bt_link(int up);                /* reads the connected name; down: releases held BLE notes */
static uint32_t bt_mode_now(void);          /* 1 = SMC DAW */
static void bt_midi_in(uint32_t pkt);       /* SMC: smc_in(pkt); MIDI: filter, ring as source 3 */
static void bt_midi_out_isr(uint32_t pkt);  /* any context: channel voice only, into a 32-entry ring */
static void bt_midi_frame(void);            /* main loop: the out ring to ble_midi_send while ble_midi_room() */
```
