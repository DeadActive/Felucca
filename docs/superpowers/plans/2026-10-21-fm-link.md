# FM-Link implementation plan

> For agentic workers: executed inline (superpowers:executing-plans), auto-approved by the user's "yes" to the design.

**Goal:** two FM-1s (Bluetooth build) in time without MIDI clock: a shared timeline over a dedicated GATT
characteristic, a fixed leader (CLK INT) and a follower (CLK LINK). **Spec:**
`docs/superpowers/specs/2026-10-21-fm-link-design.md`.

## Global constraints
- The plain build byte-identical to upstream (same day); every firmware edit outside new files inside `#if FELUCCA_BLE`.
- No update-path source changes; gates 1, 2a, 2b, 2c, 3, 4 pass; the image keeps ≥ 32,768 B of the slot.
- Integer only; 64-bit divides only by 32-bit divisors.

## Tasks
1. **Engine** (`firmware/src/fmlink.c`, `tests/fmlink_test.c`): test first, a two-unit simulation (crystals ±50 ppm
   and a random offset, 15 ms connection events with bunching, random delays, 5 % lost packets). Checks: a fresh start
   within 1 ms on both; beat positions within 2 ms for 3 minutes; a BPM change; STOP; a join on the next bar; a lost
   link for 5 s; a linked follower's own PLAY swallowed. Then the engine.
2. **Transport** (`ble_gatt.c`, `ble_central.c`, `ble_core.h`, `ble_stub.c`): the FM-Link service and characteristic in
   the device table (test: `ble_gatt_test`), its discovery on the HOST side, `ble_fml_send`, received packets queued
   with their tick and handed to `core_fml_rx`.
3. **Glue** (`bt_fml.c`, `seq.c`, `audio.c`, `params.c`, `felucca.c`, `core_ble_api.c`): CLK LINK, the block hook, the
   main loop's frame, the follower's BPM and `FOLLOWING LINK`; host test through `events_block`.
4. **Gates, docs, push, installer.**
